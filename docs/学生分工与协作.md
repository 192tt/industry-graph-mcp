# 全国产业图谱 MCP 学生分工与协作

项目服务全国不同地区和产业。北京智慧养老是本轮数据接入场景，杭州科技用于回归，再选一个非养老产业验证工具能否复用。建议以四周为一期，按实际投入调整。

## 学生 A 数据与自动更新

- 第一周对照北京主库与街道补齐表，分层抽查 30 条，覆盖成功、区级占位、同名冲突和无法匹配。提交字段字典、匹配规则、问题清单和脱敏样例。
- 第二周交付北京测试库和导入命令。保留区县、原值、候选值、来源与核验状态，并记录导入前后行数和冲突。
- 第三至四周交付可手工执行的增量任务、调度示例、变更清单和回退手册。用同一输入跑两次，验证重复执行无重复写入，模拟断网和坏数据，验证上一版仍可查询。
- 先学 Python CSV/JSON、SQLite 主键与事务、数据抽样和清洗。随后学日志、失败恢复、Windows 任务计划程序。

## 学生 B MCP 与用户体验

- 第一周本地安装并接通一个 MCP 客户端。用杭州案例走通查询和导出，整理十个真实用户问题和预期输出。
- 第二周使用 A 的脱敏样例，交付按地区、产业、区街筛选的查询和报告演示。结果显示样本范围、数据版本、来源和核验状态，并说明空结果如何调整条件。
- 第三至四周交付用户走查记录、演示脚本和简明操作手册。用杭州回归，并用一个新地区或非养老产业验证配置可替换。用同一版本核对查询、统计和导出的口径。
- 先学 MCP stdio、FastMCP 和 JSON Schema。随后学现有查询与报告接口、Flask 基础和任务式用户测试。

## 两人如何协作

1. 第一周约定共享字段，至少包括 scope、实体 ID、地区、分类、来源、核验状态和数据版本。A 生成样例和快照，B 验证能否查询、展示和导出。
2. 各自开分支，用小步 PR 交付。B 审阅 A 的字段可用性，A 审阅 B 的统计口径与证据。测试库使用脱敏样例，完整业务数据、账号凭据和运行配置保存在授权环境。
3. 每周联合演示一次。最终验收三项任务：按区街查北京养老企业并查看依据，查看一次更新差异并演示回退，切换到另一产业并导出报告。
4. 项目负责人确认数据口径、试点范围和待审变更，审核对外发布版本。
